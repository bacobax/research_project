# Experiment log

Tracks every training run across all phases of this project, in chronological order. One row
per run. Older runs (pre-dating this log) are back-filled from `phase_0/`-`phase_3/`'s exported
`results/` (CSVs, `README.md`/`FINDINGS.md`) and `RERUN_PLAN.md` — every number below is sourced
from those files, not hand-recalled. Columns whose value isn't known for a given run are left as
"—" rather than guessed.

**Task numbering**: `<phase><letter>`, e.g. `1A` = the first run under Phase 1, `2A` = the first
Phase 2 run, `3A`/`3B`/... = Phase 3 runs. `4A` is the STFT-loss ablation (Phase 4). `0A`/`0B` denote the two foundational single-song runs
that predate the phase-numbered structure entirely (Phase 0 only analyzed them, it trained
nothing new). This numbering is inferred from existing phase/run directory names, not an
existing convention in the repo — adjust if a different scheme is preferred. A rerun of an
existing task keeps that task's letter and is marked "(rerun)" in the Run column rather than
getting a new one.

## Notes on earlier phases (analysis-only, no table row — they didn't train anything new)

- **Phase 0** (validates 0A/0B above): no new training. Confirmed the train/holdout gap is a real
  generalization gap and not a pipeline bug (train-region control), and that the model beats
  non-learned token-space baselines only inconsistently at single-song scale. This is what
  justified moving to Phase 1 (data scaling) rather than distrusting the measurement itself.
- **Phase 3, gap-length x activity-band sweep** (`phase_3/results/FINDINGS.md`): pure evaluation
  of `phase1_songs17`'s and `phase2_regularization`'s existing `best_val.pt` checkpoints at
  synthetic gap lengths 1/2/4/8/16 frames — no new training. Both models were trained with
  `mask_len_max=4`, so lengths 8/16 are genuine out-of-distribution probes, not in-distribution
  generalization. Degradation is visible in both the trained and OOD range for both checkpoints;
  `phase1_songs17` sits above `phase2_regularization` on gap-only SI-SDR at nearly every length,
  consistent with (but incidental to) the seed-check's data-vs-regularization finding.
- **Phase 4, causal diagnostics (no new training except 4A)**: H1-H4 first ran on the `phase1_songs17` (1C)
  checkpoint, then (2026-10-10) on 8 clean checkpoints incl. the Phase B reruns; `phase_4/exp02` measures which
  loss term produces the gradient (STFT 1.5-6.5% of the token gradient at 26 checkpoints of 10 runs, incl. Phase 0
  `baseline`/`bigmodel`); `phase_4/exp03` + run 4A is the STFT-loss ablation. Writeups: `phase_4/README.md`,
  `phase_4/METHODS.md`, `phase_4/results/FINDINGS.md`. Note: Phase 0 `baseline` `latest.pt` (step 162k) has
  non-finite weights (the run diverged after its best checkpoint at step 78k); use `best_val`/`best`.

- **Phase 5, train/inference consistency (supervisor Q3; no new training)**: three evaluation
  experiments on the four single-song checkpoints (`baseline`, `phase1_songs01`, `phase2_regularization`,
  `phase3_regularization_seed43`). Main finding: at a real gap the context is encoded from audio
  with the gap zeroed; EnCodec's causal encoder then changes most tokens after the gap (86% at the
  next frame, ~30% after 0.85 s), and frame rounding leaves 11-33% of each real gap's silence outside
  the mask. The model's predictions are unaffected, but the corrupted context tokens are decoded
  unchanged and cost 2-4 dB SI-SDR around the gap (recovered when the predictions are written into
  clean context). Gap position, gap length, inference iterations and (for 3/4 checkpoints) precision
  are consistent; checkpoint selection on token NLL tracks audio quality poorly. Writeup:
  `phase_5/README.md` (Q3 table), `phase_5/METHODS.md`.

## Correction + grad-norm audit of the Phase B reruns (2026-10-10)

- **Do not use the launch log's `Best loss:` line as a validation number.** It is the best 1000-step-averaged *training* loss (`train.py` `self.best_loss`). Validation NLL is `val/combined_loss`; the exported values are in `phase_{1,2,3}/results/`. The earlier claim that the eps fix lowered NLL by ~0.9 nats came from comparing the two.
- **The grad_norm "spike rate" of the reruns (10-21% of steps) is a drift, not outliers.** `phase_4/exp02_gradient_spike_sources.py` back-propagates each loss term separately on saved checkpoints: the token loss accounts for essentially all of the norm (regularization seed43 @300k: token ~220, STFT ~4, waveform-L1 ~0.04; songs17 seed43 @300k: token ~54, STFT ~1.3). Measured norms match the logged ones (53.7 vs 52.9; 220.5 vs 221.9). The logged norm rises steadily through training (songs17: 3.9 -> 12.9 -> 53 at 0-50k / 100-150k / 250-300k), so a `> 100` counter fires on every late step of the regularized runs. Non-finite steps (~0.045%) are ordinary fp16 loss-scaler skips and are the same in clean and rerun logs.
- Not explained: why the token-loss gradient norm grows ~50x over training (clip is 1.0, so late-training steps are clipped by 50-220x).
