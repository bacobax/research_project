# Demo audio samples: gap fills, model by model

Generated by `scripts/make_demo_samples.py` (`uv run python scripts/make_demo_samples.py --device cuda:1`).
Each folder `gap_<id>/` holds the **same ~2 s window** (zeroed gap +- 1 s) in several versions. Listen to
`original.wav`, then `zeroed.wav`, then the model fills. The gap sits in the middle of the clip, at about 1.0 s.

## How to listen

- Use headphones. Loop the middle of the clip. The gaps are short (3-61 ms), so on a first listen most
  versions sound the same. What to listen for is a click, a dropout, or a short buzz or smear at about 1.0 s.
- Versions of one gap share **one common gain**: the original is set to -23 dBFS RMS, and no version peaks above
  -1 dBFS. Volume differences are therefore real, not normalisation artefacts. Each clip has a 10 ms fade at both
  ends. Files are 24 kHz mono, 16-bit.
- Every model output is a **splice**. Only the gap's samples (plus a 2.5 ms raised-cosine cross-fade on each
  side) come from the model. Everything else is the input audio, bit-identical to `zeroed.wav`.

`index.csv` has one row per WAV: `gap_id, kind, gap_ms, model, run, checkpoint, step, gap_si_sdr_db,
region_si_sdr_db, pick, file`. Both SI-SDRs compare against the original audio. `gap_si_sdr_db` covers only the
zeroed span. It is blank for `zeroed`, because silence has no score there. `region_si_sdr_db` covers gap +- 16
EnCodec frames (+-213 ms). `run_metadata.json` lists checkpoint steps, the held-out selection, per-gap gains and
the means over all 128 held-out gaps.

`figures/gap_<id>.png|pdf` shows the waveform (gap +- 60 ms) and log spectrogram (gap +- 300 ms) of original,
zeroed and phase6_final. `figures/scores.png|pdf` plots both scores for every version of every gap.

## Which gaps, and why these

**Real gaps (4).** These are the actual carved gaps of the pivot song (Nuvole bianche): `real0_50ms`,
`real1_20ms`, `real2_30ms`, `real3_15ms`. They are filled by the repo's own inference path,
`Trainer.inpaint_all_gaps`, with `inpaint_output_mode = splice` on the real gapped input, gaps filled in sequence.

**Held-out gaps (6)** come from the 128-gap common protocol of `phase_6/eval_final.py` (condition C: whole song
re-encoded with a real-like zeroed span, fp32, batch 1, greedy codebook decoding). None of them is hand-picked.
Each of the 128 gaps is scored by gap-only SI-SDR averaged over the 6 models. Within each length band (short = 1-2
masked frames, long = 3-4 frames), the best, median and worst gap are kept:

| gap_id | eval example | zeroed span | mean gap SI-SDR over models |
|---|---|---|---|
| `heldout_short_best` | `low_activity_len_1_14` | 3.3 ms | +12.7 dB |
| `heldout_short_median` | `high_activity_len_1_3` | 7.8 ms | -7.2 dB |
| `heldout_short_worst` | `high_activity_len_1_2` | 10.3 ms | -19.2 dB |
| `heldout_long_best` | `high_activity_len_4_12` | 60.5 ms | -0.6 dB |
| `heldout_long_median` | `low_activity_len_3_3` | 39.3 ms | -9.4 dB |
| `heldout_long_worst` | `low_activity_len_4_11` | 51.1 ms | -24.3 dB |

The held-out spans have random sub-frame edges, like the real gaps, so a 1-frame mask zeroes between about 1 and
26 ms. `heldout_short_best` is "best" partly because it is only 3.3 ms long. `heldout_long_worst` is a very quiet
passage: the common gain there is +28.5 dB, so EnCodec's noise floor is audible in every version, the original included.

All 6 models were confirmed to use the same validation holdout ranges as Phase 6, so these regions were not in
any model's training windows. The held-out scores this script recomputes match `phase_6/results/eval/records.csv`
exactly (max difference 0.000 dB for Phase 6 final over 128 gaps).

## Caveats (read before drawing conclusions)

- **The gaps are tiny.** The real gaps are 15-50 ms; the held-out ones are 3-61 ms. Even a perfect fill is hard
  to hear, and a bad one often sounds like a brief click or smear rather than a wrong note.
- **No 300k-step model reliably beats leaving the gap silent.** On region SI-SDR over all 128 held-out gaps
  (paired difference vs the zeroed input, mean +- 95% CI):
  - songs17 s43: +0.25 +- 0.39 dB; songs17 s44: +0.19 +- 0.38 dB. Neither CI excludes zero.
  - Phase 6 final: -0.73 +- 0.40 dB, i.e. worse than silence. Phase 6 best_audio: -0.78 +- 0.33 dB.
  - Only the 1M-step model (950k) is clearly better: +1.08 +- 0.51 dB. single_song averages 11.17 dB against
    11.93 dB for the zeroed input.
- **The final Phase 6 run is worse than the baseline it was meant to improve.** On gap-only SI-SDR it is 5.6 +- 1.8 dB
  below the mean of the songs17 seeds (-11.8 vs -6.3 / -6.1 dB; see `phase_6/results/eval/FINDINGS.md`, P1).
  The samples show this as well: `real1_20ms` and `real3_15ms` are Phase 6's worst real gaps (-14 and -18 dB).
  In `figures/gap_real0_50ms`, Phase 6's fill also starts with ~8 ms of near-silence before the waveform resumes.
- Splice output protects the context. Without it, re-decoding the whole window costs about 6 dB of region SI-SDR
  (FINDINGS P4). Any audible difference between versions therefore comes from the gap alone.
- SI-SDR punishes a plausible fill with the wrong phase as harshly as silence. Listening can rank fills
  differently from these numbers, and that disagreement is part of what the samples are for.

These samples illustrate the findings above. They are not chosen to hide them.
